# Prompt สำหรับ agent ที่ต่อ kie.ai ไว้แล้ว

> ก๊อปทั้งบล็อกด้านล่างส่งให้ agent อีกตัวได้เลย

---

## งาน

ต่อ kie.ai เข้ากับบอท LINE OA ของ **ร้านขนมปัง สดสดสด** ให้บอทส่งรูปสินค้าให้ลูกค้าได้เมื่อลูกค้าขอดูรูป

## repo

- Node.js + `@line/bot-sdk` ทำหน้าที่เป็น Worker รับ webhook จาก LINE
- ตรรกะการตอบอยู่ที่ฟังก์ชัน `buildReply()` ใน `src/server.js` ตอนนี้ยังเป็นแค่ทักทาย + echo
- ไฟล์ "สมองร้าน" ที่เป็นแหล่งข้อมูลจริง — **อ่านทั้ง 3 ไฟล์ก่อนเริ่มเขียนโค้ด**
  - `products.md` — รายการสินค้าและราคา
  - `context.md` — น้ำเสียง กติกาต่อรอง และ **กติกาเรื่องรูปภาพ (ข้อ 6)**
  - `promotions.md` — โปรโมชั่น (ตอนนี้ว่าง)

## สินค้าที่ต้องมีรูป (ยึดตาม `products.md` เท่านั้น)

| สินค้า | ราคา |
|---|---|
| ขนมปังชิโอะปัง | 15 บาท / ชิ้น |
| Box Set 1 (เค้กกล้วยหอม 1 + ชิโอะปัง 1 + น้ำผลไม้ 1 กล่อง) | 59 บาท / เซ็ต |
| บราวนี่ (ชิ้น) | 39 บาท |
| บราวนี่ (กล่อง 6 ชิ้น) | 189 บาท |

ถ้าลูกค้าขอรูปของที่**ไม่อยู่ในตารางนี้** → ห้าม gen ให้ ให้ตอบตามข้อความ fallback ด้านล่างแล้วส่งต่อแอดมิน

## สถาปัตยกรรมที่ต้องการ: pre-generate แล้ว cache ไว้ (สำคัญ)

**อย่า gen รูปสด ๆ ตอนลูกค้าทัก** เพราะ:

1. LINE รอ webhook แค่ ~10 วินาที ถ้าช้าจะ retry ซ้ำ แต่การ gen รูปกินเวลาหลายสิบวินาที
2. ถ้าตอบไม่ทันด้วย `replyMessage` (ฟรีภายใน 24 ชม.) ต้องไปใช้ `pushMessage` ซึ่ง **กินโควตารายเดือน = มีค่าใช้จ่ายจริง**
3. สินค้ามีแค่ 4 รายการและไม่ค่อยเปลี่ยน จ่ายค่า gen ซ้ำทุกครั้งที่มีคนถามคือเผาเงินเปล่า

**ให้ทำแบบนี้แทน**

- เขียน script แยก (เช่น `npm run gen:images`) ที่ gen รูปสินค้าทั้ง 4 รายการครั้งเดียว แล้วเก็บผลลัพธ์ไว้
- ตอนรัน bot ให้อ่านรูปจาก cache แล้วตอบด้วย `replyMessage` → เร็ว ฟรี ทันใน 10 วินาที
- cache เก็บ mapping `ชื่อสินค้า → URL รูป` ลงไฟล์ เช่น `image-cache.json` และ **commit ได้** (เป็นแค่ URL ไม่ใช่ความลับ)
- มีคำสั่ง re-generate เผื่อเจ้าของร้านอยากเปลี่ยนรูป

## ข้อกำหนดฝั่ง LINE

- ส่งรูปด้วย message type `image` ต้องมีทั้ง `originalContentUrl` และ `previewImageUrl`
- URL ต้องเป็น **HTTPS ที่เปิดสาธารณะเข้าถึงได้จริง** และเป็น JPEG หรือ PNG
  → ถ้า URL ที่ kie.ai คืนมาเป็น URL ชั่วคราวที่หมดอายุ **ต้องดาวน์โหลดมาโฮสต์เองที่ HTTPS ถาวร** ไม่งั้นลูกค้าจะเห็นรูปพัง
- ต้องตอบ HTTP 200 กลับ LINE ก่อน แล้วค่อยประมวลผล (ของเดิมทำไว้แล้วใน `src/server.js` อย่าไปรื้อ)
- อย่าไปแก้ส่วนตรวจลายเซ็น `middleware()` — เป็นตัวกันคนยิง endpoint มั่ว

## ความลับ

- อ่าน API key จาก **`process.env.KIE_API_KEY`** เท่านั้น (มีช่องไว้ให้แล้วใน `.env.example`)
- ⚠️ **repo นี้เป็น public** ห้าม hardcode key ห้าม commit `.env` ห้าม log key ลง console หรือ error message
- ก่อน commit ให้ `git diff --cached` เช็กว่าไม่มี key หลุด

## กติกาการตอบ (ห้ามละเมิด — อยู่ใน `context.md` ข้อ 6)

- **ห้ามบอกลูกค้าว่า "สร้างรูปภาพไม่ได้"**
- **ห้ามบอกว่าตัวเองเป็น AI / บอท / โมเดล** — รูปเป็นหน้าที่ของระบบร้าน
- ห้ามอธิบาย error ทางเทคนิคให้ลูกค้าฟัง
- ถ้า gen ไม่สำเร็จ / ไม่มีรูปใน cache / ลูกค้าถามสินค้านอกรายการ → ตอบข้อความนี้เป๊ะ ๆ:

  > รุ่นนี้ยังไม่มีรูปในระบบค่ะ เดี๋ยวแจ้งแอดมินส่งรูปให้นะคะ

  แล้วส่งต่อแอดมิน
- น้ำเสียงร้าน: ตอบสั้น ๆ ลงท้าย คะ/ค่ะ ทุกข้อความ
- ถ้าลูกค้าถามว่า **"ของจริงหน้าตาแบบนี้ไหม"** → ห้ามยืนยัน ให้ส่งต่อแอดมินขอรูปถ่ายจริง
  (รูปที่ระบบสร้างเป็นภาพประกอบ ไม่ใช่ภาพถ่ายสินค้าจริง)

## prompt ที่ใช้ gen รูป

ให้รูปทั้ง 4 ใบดูเป็นชุดเดียวกัน เหมือนถ่ายในร้านเดียวกัน:

- เบเกอรี่ไทยโฮมเมด แสงธรรมชาตินุ่ม ๆ พื้นไม้ ฉากหลังเรียบ
- มุมกล้อง ระยะ และโทนสีเดียวกันทุกใบ
- จัตุรัส 1:1 เหมาะกับการแสดงผลใน LINE
- ห้ามมีตัวหนังสือ โลโก้ ลายน้ำ หรือมือคนในรูป
- ต่อสินค้า: ชิโอะปัง = ขนมปังเกลือญี่ปุ่นชิ้นเดียว · Box Set 1 = กล่องเปิดเห็นของ 3 อย่าง ·
  บราวนี่ชิ้น = บราวนี่ชิ้นเดียว · บราวนี่กล่อง = กล่อง 6 ชิ้นเรียงกัน

## ส่งมอบ

1. โค้ดที่ต่อ kie.ai + script pre-generate + cache
2. `buildReply()` ตรวจจับว่าลูกค้าขอรูป แล้วตอบรูปจาก cache
3. อัปเดต `README.md` บอกวิธีรัน script gen รูปและวิธีเปลี่ยนรูป
4. ทดสอบเคส: ขอรูปสินค้าที่มี · ขอรูปสินค้าที่ไม่มี · kie.ai ล่ม (ต้องได้ข้อความ fallback ไม่ใช่ stack trace)

## สิ่งที่ผมไม่รู้ ให้คุณเช็กเอง

ผมไม่มี doc ของ kie.ai เลยไม่ได้ระบุ endpoint / ชื่อ model / รูปแบบ response ให้
**ห้ามเดา** ให้เปิด doc จริงแล้วยืนยัน 3 เรื่องนี้ก่อนเขียนโค้ด:

1. endpoint กับ auth header ที่ถูกต้อง
2. โครงสร้าง response — คืน URL หรือ base64 และ **URL อยู่ถาวรหรือหมดอายุ**
3. ราคาต่อรูป และมี rate limit ไหม
